# fmerge

不使用 WebView / Electron 的原生 Flutter 桌面文本比较与三方合并工具。交互参考 TortoiseGitMerge，支持文本 Diff、三方 Merge、文件保存、Git 外部工具接入和按块暂存；不包含补丁文件应用或完整 Git 客户端。

正式工程位于仓库根目录。

## 从源码运行

已验证环境：Flutter **3.47.9 stable**（Dart **3.13.7**）。CI 固定使用此版本。依赖从 `https://pub.dev` 获取；使用镜像时请自行配置环境，不要把个人镜像地址提交到锁文件。

macOS Release 构建后可直接打开 `build/macos/Build/Products/Release/fmerge.app`，或使用 `tool/fmerge`。

```sh
flutter --no-version-check pub get --enforce-lockfile
flutter --no-version-check run -d macos
# 构建本平台应用
flutter --no-version-check build macos --release
python3 tool/package.py
```

Windows / Linux 已生成原生 runner 和 CI 构建入口，但本机没有完成这两个平台的构建与人工验收。不要把 macOS 测试等同于三平台验收。

## 文件比较

- 打开按钮和 ⌘/Ctrl O 直接显示系统文件选择器，支持一次多选两个文件；只选一个时继续选择右侧文件，取消选择保留当前会话。工具栏支持交换左右顺序，保留未保存文本与撤销历史（指定输出位置或三方合并时不交换）。
- 原生可编辑双栏，语法高亮、整行和行内差异、真实行号与同步滚动。
- “视图”菜单可切换“自动换行”“单词差异”“移动代码”，设置中也提供对应开关，并跨启动保留。默认关闭自动换行、使用字符级高亮、开启移动识别；快捷键分别为 ⌘/Ctrl Alt Z、⌘/Ctrl Alt I、⌘/Ctrl Alt M，可自定义。
- 自动换行保留真实行号，每个对齐行按双方实际段落的较大高度显示；窗口、字体、Tab 宽度或文本变化时重算，概览和导航沿用同一高度映射。不插入换行、空格或占位文本；三方结果栏独立换行。启用后首次布局需测量可见文档行，未完成极端大文件换行性能验收。
- 单词差异按完整标识符/数字突出修改，可切回字符级；两种模式均保持字素边界，不拆开 Emoji。只改变行内高亮和导航片段，不改变差异块采用与三方合并判断。
- 双栏比较以蓝色显示移动的连续代码块，在底部行详情点击“移动代码”可跳到另一侧对应行。仅识别具有唯一非空行锚点、逐行精确相同、至少两行且合计至少 16 个字符的块；重复代码、复制以及移动后修改或调整缩进的代码可能不标记。三方模式不推测双方之间的移动关系。
- 每个文件底部独立显示编码、换行、语言与行号；点击弹出列表。语言菜单支持 JSON、JSONC、C、C++、Rust 等格式或纯文本，也可恢复按后缀自动识别，仅影响语法高亮。输入编码按所选编码重新读取该文件，丢弃该侧未保存修改前需要确认；共同祖先编码变化会重新创建合并并执行未保存保护。结果/未命名文本的编码与可编辑文件的换行设置在保存时应用，格式修改也会计入未保存状态。
- 虚拟占位不进入文档、剪贴板或保存文件；不会为了对齐往文件插入空行。
- 右侧默认可编辑；左侧需点击“左侧编辑”。支持逐块采用左侧；启用左侧编辑后可逐块采用右侧。比较菜单支持按两种顺序组合双方区块。
- F7 / Shift F7 跳转差异，每次将目标首个真实行居中并移动光标、焦点，当前行以强调色边框标明；纯插入/删除定位到有真实文本的一侧，首尾受滚动边界限制；⌘/Ctrl F 查找与替换；⌘/Ctrl G 跳转行。
- ⌘/Ctrl S 保存当前编辑目标；⌘/Ctrl Shift S 另存并选择编码和换行。
- “忽略空白”只忽略行首、行尾的空格与 Tab，保留行内空白差异；另可忽略大小写与换行风格。忽略只影响显示，不改写源文档。旧版本的空白忽略选项迁移为行首/行尾规则。
- 顶部只保留一行：左侧按文件、编辑、视图、导航、比较（或合并）、工具、帮助组织图标菜单，右侧放常用快捷按钮。菜单与按钮共用可选的底部文字；窗口变窄时先临时隐藏文字，再按优先级收起快捷按钮，放大后自动恢复，不改写显示偏好。收起的操作始终可从分类菜单进入，不再依赖横向滚动或“更多”菜单。菜单显示快捷键和开关状态，macOS 系统菜单提供相同分类。视图菜单提供概览条、行详情、自动换行、只看差异、空白字符、高亮与工具栏文字开关；忽略规则、行内高亮模式和移动识别位于比较 / 合并菜单。
- 工具栏“重新加载”从磁盘重新读取双方文件，适用于外部编辑器修改后手动刷新；有未保存修改时可保存、不保存或取消。未命名文本不启用此操作；保留输入编码和语言选择。三方模式重新读取双方和祖先并重新生成合并结果。
- 右侧差异概览以两条色带显示双方差异和当前视口，支持点击、拖动定位；三方模式中黄色标记表示该侧相对祖先的删除。折叠视图使用同一显示行映射。
- “编辑”菜单提供剪切、复制、粘贴、全选和查找替换；“导航”菜单提供跳转行及上一处/下一处差异、行内差异和冲突；概览条、行详情的开关位于“视图”菜单，两项显示偏好跨启动保留。行内导航默认 Alt F7 / Shift Alt F7，选中当前侧的变化片段；整行在该侧不存在时定位另一侧。三方模式在当前输入中导航其相对祖先的变化。
- 底部行详情使用紧凑标题栏和上下两行代码；侧别、真实行号固定在左侧，代码共用横向滚动，保留行内差异高亮；相同文本使用中性背景，占位明确显示“此侧无对应行”。关闭和移动跳转位于标题栏。焦点在合并结果时显示当前冲突的双方首行；结果中的非冲突行不猜测输入对应关系。
- 行详情与编辑器一样最多渲染单行前 32000 个 UTF-16 位置，截断处显示省略号，不影响源文本、复制或保存。
- 每个文档底部可独立选择 Tab 2 / 4 / 8 显示宽度，默认 4；不转换 Tab、不改变输入缩进规则、未保存状态或撤销历史，交换左右时跟随文件，重新加载后保留。双栏底部分别显示删除与新增行数，三方输入分别显示相对共同祖先的增删统计；统计遵循当前比较规则。
- 双栏比较可只显示差异及前后各 X 行，默认 3 行，可在“设置 → 比较”中配置 0–1000 行；显示偏好与行数跨启动记住。顶部持续标明当前上下文行数及省略段数，可点击“显示全文”退出；折叠后各侧仍显示文件原始行号，不按可见行重新编号；省略内容使用带底色、边框与行号栏省略标记的双行提示带，标明隐藏行数及本侧原始行号范围。点击提示带可临时显示全文并定位该区域，顶部“显示全文”保留当前原始行位置。编辑、查找或跳转进入隐藏行时临时展开，保留偏好供下次打开使用。折叠不改写文档、行号或复制内容。三方合并保持完整视图。

## 快捷键与设置

“设置 → 编辑器与外观”支持跟随系统、亮色、暗色模式，亮暗主题分别保存。内置 GitHub Light、GitHub Dark、Tokyo Night 和原有 fmerge Dark；切换时即时更新界面、语法高亮、差异底色、行内标记和概览条，保留文本与撤销历史。偏好跨启动恢复。

每个亮色/暗色主题下的“自定义”可从当前配色创建主题，配置名称及界面、差异、语法高亮共 24 项颜色，并查看代码和差异预览；保存后应用，取消不改动当前主题。自定义主题支持编辑、另存为新主题和删除，删除后回到原先的内置选择。亮暗主题分别保存，预览另一种外观时可切换对应模式。

“导出”可将内置或自定义主题保存为 `.fmerge-theme.json`；“导入主题 JSON”读取 fmerge 版本 1 的主题格式（不是 Zed/VS Code 原生主题文件）。同名导入自动追加编号，不覆盖已有主题；无效格式、未知颜色字段或超过 1 MB 的文件会显示错误并保留现有设置。导出包含完整颜色快照，手写文件可以只覆盖部分颜色，其余继承 `base`：

```json
{
  "format": "fmerge-theme",
  "version": 1,
  "name": "我的夜色",
  "base": "tokyoNight",
  "colors": {
    "bg": "#151820",
    "panel": "#1b2030",
    "accent": "#80b0ff",
    "keyword": "#c5a0ff",
    "selection": "#80b0ff40"
  }
}
```

`base` 支持 `githubLight`、`githubDark`、`tokyoNight`、`fmergeDark`，决定主题的亮暗类型。颜色使用 `#RRGGBB` 或 `#RRGGBBAA`，末两位是透明度。完整字段可从任一内置主题导出后查看：

| 分组 | 颜色字段 |
| --- | --- |
| 界面 | `bg`、`panel`、`elevated`、`border`、`muted`、`ink`、`accent`、`green`、`red`、`amber` |
| 差异与选择 | `addedBg`、`removedBg`、`addedInline`、`removedInline`、`movedBg`、`movedInk`、`conflictBg`、`selection` |
| 语法高亮 | `keyword`、`string`、`number`、`comment`、`title`、`meta` |

设置按比较、编辑器与外观、快捷键、Git 集成、文件与权限分组。点击“快捷键”中的键位可录制新组合，支持冲突提示、清除绑定和恢复默认；应用菜单、工具栏提示、编辑器和实际按键使用同一配置。普通文字键需搭配修饰键，功能键可单独使用。

## 三方合并

三方合并只通过 Git mergetool 或命令行进入；欢迎页、工具栏、系统文件菜单和最近记录均不提供合并入口。

- 输入共同祖先和左右两个版本，分别显示双方相对祖先的差异，并共享同一视觉行映射。
- 独立修改自动合并；同一范围双方不一致时保守标记为冲突。
- 支持采用任一侧、左右顺序组合、保留祖先，以及手工编辑后标记解决。
- 结果可直接编辑；冲突选择、手工修改和解决状态共用撤销/重做历史。
- 结果编辑之外的手工修改不会因重新选择其他冲突块而整份丢失。
- F8 / Shift F8 导航冲突；结果栏可打开共同祖先供参考。
- 主工具栏优先保留“上一冲突 / 下一冲突”双箭头按钮（F8 / Shift F8），循环定位结果栏光标并将目标行居中，即使该行已经可见，手工编辑后按更新的冲突位置跳转；包含已确认冲突，便于回查。
- 输入与结果之间使用 40 像素高的紧凑合并操作栏：左侧冲突导航，中间采用操作，右侧确认状态；按钮限制宽度，长来源名称省略并提供悬停全文。窗口变窄时收起组合按钮，保留左右采用；查看祖先、两种组合顺序与手工解决状态集中在“合并”菜单。无冲突时显示 32 像素高的提示条，上下编辑区按扣除操作栏后的实际空间分配。
- 未确认冲突禁止保存；关闭未保存结果需要确认。仅最终结果已保存且没有待处理冲突时，mergetool 返回 0。

三方输入保持只读；更换输入文件需重新通过命令行启动。底部切换输入编码会重新计算合并，并执行未保存保护。合并判断始终使用精确文本，不受“忽略空白”等显示选项影响。

### 看清 Git 合并来源

Git mergetool 的 `LOCAL / REMOTE`、`ours / theirs` 表示操作角色，不固定表示“我的 / 别人的代码”，`REMOTE` 也不一定来自远端仓库。

- 普通 merge 显示“当前分支 / 合入版本”，按钮为“采用当前分支 / 采用合入版本”。
- rebase 显示“正在将 feature 变基到 main”，左侧为“目标历史”（目标分支加上已重放提交），右侧为“本次提交”（正在重放的原提交）；按钮随之改为“采用目标历史 / 采用本次提交”。
- 输入栏显示提交短哈希与摘要，来源详情提供 `ours / current / LOCAL` 和 `theirs / incoming / REMOTE` 对照。分支引用不唯一时显示提交哈希，避免猜测来源分支。

打开三方合并时，只有输出路径属于当前 Git 冲突、输入内容与索引及来源提交吻合，才显示操作角色；支持 linked worktree。普通文件、已解决的冲突、被修改或交换的输入，以及无法核验来源的情况显示“左侧输入 / 右侧输入”及实际路径。没有可确认的 Git 上下文时，`--local / --remote` 仅表示左右输入顺序。

macOS 沙盒中若仓库根目录尚未授权，可点击“识别 Git 来源”，在系统面板中选择仓库根目录或其父目录后重试；无法识别不会阻止继续合并。重新加载文件时会重新核验来源信息。

## 文件完整性与保存

- 自动模式按 BOM 识别 UTF-8 BOM、UTF-16 LE/BE，无 BOM 严格按 UTF-8 读取，不做概率式编码猜测。自动读取失败时可为该文件选择读取编码，打开后也可在文件底部切换 UTF-8、UTF-8 with BOM、UTF-16 LE/BE（包括无 BOM 文件）、Latin-1、GBK、Big5、Shift-JIS、EUC-JP、Windows-1250～1258、CP437/737；合并结果可独立选择保存编码。手动选择优先于 BOM，仅移除与所选编码相符的 BOM；重新加载沿用当前编码和语言选择。
- 旧编码读取必须能重新编码回原始字节，保存必须能重新解码回完整文本；不允许替换字符、截断后缀或写入越界字节。不能精确往返的合法别名字节也会保守拒绝，可先用其他工具转为 UTF-8。无损校验不能判断用户是否选对了编码，只能避免转换造成内容丢失。GBK 不等于完整 GB18030；GB18030 和 EUC-KR 暂不支持，请先转为 UTF-8。EUC-KR 因依赖的映射表与标准不符未启用；EUC-JP 的 A1 BD 已修正为标准 U+2015。
- 原样保留未编辑文件、BOM 和末尾换行。混合换行中能对应的原始行保留各自换行，新行使用主导风格；另存可强制 LF / CRLF / CR。
- 同目录临时文件写入并刷新后 rename；写入失败保护原文件。保存前检测外部修改，要求另存或显式覆盖。
- 可保留 `.bak` 备份；保留 POSIX 权限位；通过符号链接保存时更新实际目标并保留链接。
- 原子替换可能改变 inode，不保证保留所有平台的扩展属性、ACL 或硬链接关系。并发写入不合作的外部程序仍有极短的检查与替换竞争窗口。
- 保存期间继续输入的新修改仍保持未保存，不会误报已保存。
- 文件读取上限 32 MiB；语法高亮上限 4 MiB；极长行有渲染限制。未完成极端大文件与无障碍审计。

## macOS 文件授权

保留 App Sandbox。系统文件选择器授予选中文件的权限；安全保存需要在同目录创建临时文件与备份，首次保存或通过 Git 接收外部路径时，可能要求选择所在目录或其父目录。

记录用户在系统选择器明确选择的文件与目录安全书签，下次启动恢复授权；最近记录在读取前检查权限，旧记录或失效授权通过系统目录选择器重新授权。“设置 → 撤销已授权文件与目录”清除两类书签，重启后完全生效。不会自动授予整个磁盘访问。

设置和最近文件只保存偏好与路径，不保存文件正文。macOS 位于应用沙盒内的 `Library/Application Support/fmerge`；其他平台使用标准用户配置目录。

## 命令行与 Git

```sh
./tool/fmerge LEFT RIGHT
./tool/fmerge --base BASE --local LOCAL --remote REMOTE --output MERGED
./tool/fmerge --read-only LEFT RIGHT
./tool/fmerge --help
```

- `--wait`：默认等待当前窗口关闭，不会将进程启动成功当作合并成功。
- `--auto-close`：保存成功后尝试关闭；若保存期间又有修改，仍执行未保存保护。
- 兼容 `/base:... /mine:... /theirs:... /merged:...` 路径形式。
- `--output` 在比较模式指定右侧保存目标，避免意外覆盖临时输入。
- 退出码：0 = 比较正常结束，或合并最终结果已保存且冲突全部处理；1 = 合并取消/未完成；64 = 参数错误。
- 首次路径授权被取消或文件读取失败会明确报错，不会偷偷打开示例或空白内容。

### 按块暂存，拆分提交

在 diff 编辑区选择修改过的代码行，在选择范围内右键，点击“暂存所选代码块”。未选择文本时使用右键位置所在的真实行：

1. 先保存当前文件；暂存使用磁盘文件与索引的精确差异，不受空白显示规则影响。
2. 只暂存与所选真实行相交的 Git 差异块；块内只选一行也会暂存整个 Git 块，不承诺逐行暂存。纯删除块按工作区中的相邻行边界定位，不将整个上下文范围当成修改。
3. 在终端执行 `git diff --cached` 检查本次提交，再执行 `git commit`。其余修改保留未暂存，工作区文件保持不变。

界面没有独立暂存对话框和取消暂存入口；需要调整已暂存内容时使用 Git 或其他 Git 客户端。仅更新索引，不自动执行 commit。文件或索引变化时拒绝过期补丁；编辑器未保存内容需先保存。支持保留已有部分暂存内容、CRLF 和缺少末尾换行。

[TortoiseGit 官方的部分提交说明](https://tortoisegit.org/docs/tortoisegit/tgit-dug-commit.html#tgit-dug-commit-restore) 使用的是右键 `Mark this block`、再 `Use left file except marked blocks` 与提交后恢复文件，并不是直接的 Git index stage/unstage。本应用采用相似的右键操作位置，实际执行 Git 按块暂存。

需要本机安装 Git。macOS 自动查找 PATH、Homebrew、Xcode 或 Command Line Tools 中的实际 Git，避开不能在沙盒运行的 `/usr/bin/git` 入口；自定义位置可用 `FMERGE_GIT` 指定。仅支持已跟踪的普通文本文件；未跟踪文件需先通过 Git 加入跟踪，二进制、符号链接、子模块、未解决冲突和权限变化会明确报错。macOS 沙盒中遇权限错误时，可点击错误提示中的“授权仓库”，选择仓库根目录；Git worktree 的索引位于外部目录时需授权共同父目录。实际沙盒 Git 子进程已通过临时仓库验证；系统目录授权仍需人工验收。

“设置 → Git 集成”（更多菜单也可直达）分别提供比较、合并配置的复制按钮；完整命令可展开查看。也可按下面的例子配置；应用不会替用户修改全局 Git 配置：

```sh
git config --global diff.tool fmerge
git config --global difftool.fmerge.cmd '"/absolute/path/to/fmerge/tool/fmerge" "$LOCAL" "$REMOTE"'
git config --global merge.tool fmerge
git config --global mergetool.fmerge.cmd '"/absolute/path/to/fmerge/tool/fmerge" --base "$BASE" --local "$LOCAL" --remote "$REMOTE" --output "$MERGED"'
git config --global mergetool.fmerge.trustExitCode true
```

安装到 Applications 后，可把命令路径换成 `/Applications/fmerge.app/Contents/MacOS/fmerge`。Windows 可直接使用 `fmerge.exe`，或用 `tool/fmerge.ps1` 保留参数和退出码。

## 大文件性能

本轮移除默认比较的不必要换行/键数组、未改动行的空装饰，复用显示布局，并优化折叠区间。50 万行稀疏修改的 AOT 核心比较中位数为 195 ms，独立进程峰值 RSS 为 270 MiB；基线分别为 344 ms / 370 MiB。该测量不包含完整编辑器和渲染，不能等同于整机响应或内存上限。

进一步优化了任务调度：每个会话最多一个比较任务，连续请求合并为最新状态；精确换行重建也在后台执行。编辑器复用正文快照和未保存状态判断，10 万行控制器/会话基准的光标移动与状态读取由 47.73 ms 降为 0.03 ms（Flutter test JIT，不含实际绘制，也不代表连续编辑延迟）。

复现方法、原始数据、密集修改降级和后续优化顺序见 [大文件性能评估](performance.md)。32 MiB 单文件上限保持不变。
