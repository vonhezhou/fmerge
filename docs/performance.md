# 当前版本性能评估

适用版本：0.1.0 预览版。评估状态更新于 2026-11-05。

当前版本尚未完成系统性的性能评估，暂不能给出推荐文件规模、打开耗时、交互延迟或内存上限。单文件 32 MiB 是读取保护阈值，不表示所有低于该阈值的文件都已通过流畅性验收。

## 现有保护与行为

| 项目 | 当前行为 | 适用边界 |
| --- | --- | --- |
| 文件读取 | 单文件超过 32 MiB 时拒绝打开。 | 按磁盘字节数判断；当前仍整份读取、解码和建模，不是流式比较。多侧文件及编辑器、比较结果和历史会共同占用内存。 |
| 语法高亮 | 正文超过 4 × 1024 × 1024 个 UTF-16 代码单元，或任一行超过 32000 个 UTF-16 代码单元时，关闭该文档的语法高亮。 | 大小阈值不是磁盘字节数；关闭语法高亮后仍可进行文本比较、显示差异标记、编辑和保存。阈值内采用全文后台解析。 |
| 极长行显示 | 单行最多渲染前 32000 个 UTF-16 位置。 | 显示截断不改变源文本、复制和保存内容。 |
| 大片差异 | 超过 2048 视觉行的单个修改块使用整行高亮；比较也可能因预算耗尽而简化结果。 | 行内细节可能减少，采用、复制和保存仍保留完整文本；不能仅凭耗时较短判断精细比较已经完成。 |

## 评估范围与缺口

目前保留了核心比较基准、控制器基准和 macOS Release 测量入口，以及调度、取消、历史预算等行为回归测试。它们提供测量和正确性验证能力，尚不足以说明当前版本在不同文件规模下的完整使用体验。

| 场景 | 需要覆盖的条件 | 需要记录的指标 |
| --- | --- | --- |
| 双侧打开与比较 | 从小文件到接近单侧 32 MiB；相同、稀疏修改、密集重写、重复行；同时记录行数和行长分布。 | 打开至首次可交互、初次比较耗时、是否简化差异、进程峰值 RSS。 |
| 高亮与布局 | 高亮阈值上下、不同语言、超长行；自动换行开启与关闭。 | 高亮完成耗时、布局耗时、滚动帧时间和内存。 |
| 编辑与保存 | 连续输入、多行粘贴、查找替换、撤销重做、保存；包含真实中文输入法。 | 同步处理耗时、系统输入到屏幕延迟、后台比较完成时间、保存耗时。 |
| 三方合并 | 初始计划、冲突采用、结果栏手工编辑、撤销和保存。 | 各阶段耗时、交互帧时间、内存增长和历史行为。 |
| 持续使用与平台 | 多会话、反复打开关闭、长时间编辑；macOS / Windows / Linux 目标硬件。 | 冷启动、持续内存变化、关闭后的内存表现、各平台差异。 |

以上场景尚未形成完整的当前版本测量结果。发布时的人工验收项见 [发布验收清单](releasing.md)。

## 测量入口

### 核心比较与折叠

```sh
dart compile exe tool/benchmark_diff.dart -o /tmp/fmerge-diff-bench
/tmp/fmerge-diff-bench 100000 sparse
/tmp/fmerge-diff-bench 500000 sparse
/tmp/fmerge-diff-bench 100000 dense
```

该工具测量生成文本的核心比较、折叠耗时和基准进程峰值 RSS，输出输入字节数与差异简化标记。它不经过应用文件读取入口，不受 32 MiB 读取保护约束；扩大行数前需自行检查样本大小。结果不包含完整编辑器、文件读写、布局或绘制。

### 控制器导航

```sh
flutter --no-version-check test --no-pub --reporter expanded tool/benchmark_editor.dart
```

可通过 `--dart-define=LINES=500000` 改变规模。该工具在 Flutter test JIT 环境测量正文不变时的光标移动与未保存状态读取，不包含 Widget 布局和绘制，也不能用于推断实际输入延迟。

### macOS Release 应用

```sh
python3 tool/test_macos.py --performance
# 测量入口占用本地 Release 构建产物，完成后恢复正常产品入口：
flutter --no-version-check build macos --release
```

当前入口固定生成两侧各 10 万行的 Dart 文件，在一个进程中执行三次文档重载，每轮进行五次程序化局部插入与撤销、一次显式比较及 120 次远距离滚动。报告输出到系统临时目录中的 `fmerge-performance-native.json`。

该样本超过语法高亮大小阈值，不能验证大文件开启高亮的表现。同步编辑耗时不包含系统输入到屏幕延迟；打开至比较完成不等同于冷启动或首次像素呈现；每轮仅五次编辑，报告中的编辑 P95 实际取到该轮最大值，不能作为可靠的尾延迟结论。滚动帧按引擎时间戳筛选并等待批量报告，构建与光栅耗时分别记录。RSS 未强制 GC，不是长期稳态或应用内存上限。

## 结果记录要求

后续评估应记录被测提交、工具链、设备及内存、操作系统、窗口尺寸、显示缩放、比较规则、高亮和换行设置，以及输入字节数、编码、行数和差异分布。记录独立进程次数、预热方式、指标口径及原始数据路径；冷启动与进程内重载分别统计。

核心基准、同步编辑耗时和真实交互体验分别报告；对于简化差异、测量失败及未覆盖场景明确标注。完成测量后，再据此填写当前版本的结果和适用范围。

## 本轮实现与局部查找测量（2026-11-05）

新增 `flutter --no-version-check test --no-pub tool/benchmark_find.dart --reporter expanded`，默认 64000 行、每行一个 `x`，验证全部 64000 个匹配。`--dart-define=LINES=...` 可改变行数。在当前 macOS / Flutter test JIT 环境，优化后三轮完整查询耗时为 69、44、41 ms；评审时同类临时用例单次为 2384 ms。它验证了重复行扫描改为行偏移二分定位的局部收益，不是 Release 应用输入延迟、跨设备或稳定尾延迟结论。

本轮还将三方初始合并计划移到后台，手工结果编辑按共享分段裁剪差异范围；焦点磁盘检查使用后台流式摘要，合并同一基线的重复请求；自动换行复用未变行的高度测量。编辑后的完整快照和对齐行高度数组仍会按需创建，开启换行的首次测量仍遍历可见文档行。这些路径尚未形成完整 Release 性能评估，不能据此放宽文件上限或承诺所有场景流畅。
